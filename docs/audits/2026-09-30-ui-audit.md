# HexTail UI audit — September 30, 2026

Branch: `audit-ui`. Baseline: `c12b105` / release `0.2.2`.

Fix Elastic range correctness and configuration preservation first. Then make the controls reachable and the setup state understandable. Theme polish comes after those changes.

This audit covers the desktop shell, file/search tabs, log rows and inline context, search, errors, all settings sections, Elastic setup, source selection, and time ranges. It records proposed changes; application behavior has not been changed.

## Evidence and limits

- Read all app XAML and styles, then traced the commands, settings persistence, source health, and Elastic query flow.
- Rendered Avalonia controls with Skia on the headless platform at widths of 720, 1280, and 1920 pixels. Inspected Cyber Tail, Catppuccin Mocha, and Spotify settings renders.
- Ran two temporary diagnostic tests with synthetic Elastic metadata. They captured the layout and reproduced the range/configuration findings below. The temporary test and rendering configuration were removed afterward.
- After removing the probes, the unchanged Release test suite passed: 188 tests, with 47 existing analyzer warnings.
- Calculated contrast from the palette's sRGB values. Used WCAG as a design benchmark, not as a claim of certified native-app compliance.
- No real Elastic cluster, operating-system credential dialog, screen reader, display scaling, or native Windows/macOS interaction was exercised. Async races identified by source review are explicitly marked as risks rather than reproduced failures.

Saved [measurements and probe results](evidence/ui-2026-09-30/measurements.txt) accompany the screenshots. The diagnostic source remains locally at `/tmp/hextail-ui-audit/UiAuditProbe.cs`; the reproduction steps and actual results are recorded here so the findings do not depend on that temporary file.

## P0 — correctness and preservation

### 1. Applying a range must replace the result set

**Confirmed by probe and source.** Append a row, then apply an entirely disjoint absolute time range. The previous row remains in `FileTabState.Buffer`. `AppState.SetElasticTimeRange` updates expressions and resets the tailer's cursor, but neither clears the buffer nor emits `SourceReset`. Subsequent initial results append to the old results. Reapplying an overlapping range can replay rows as well.

There is also an in-flight-query risk: `SetTimeRange` mutates cursor fields while `PollOnceAsync` is awaiting network calls, so an older poll can later emit rows and commit its previous cursor. This race was identified from source, not reproduced with a real cluster.

**Change:** Treat Apply as a new query generation. Cancel or invalidate the old request, replace the old rows when the new query is accepted, and keep the existing search definitions attached to the replacement buffer. Handle a failed reload without presenting old rows as the newly applied result.

**Acceptance:** Range A → disjoint B contains only B; applying B twice adds no duplicates; a deliberately delayed A response cannot overwrite B or add A rows. Search counts and inline selection remain consistent after replacement.

Evidence: [AppState.SetElasticTimeRange](../../src/HexTail/Application/AppState.cs), [ElasticTailer.SetTimeRange/PollOnceAsync](../../src/HexTail/Elastic/ElasticTailer.cs), [source event handling](../../src/HexTail/Application/AppState.cs).

### 2. Both endpoints need one clock, ordering checks, and safe parsing

**Confirmed by probe.** With a frozen clock of `2026-09-30T12:00:00Z`, From=`now-5m` and To=`now-1m` sends `11:54 → 11:59`. Under normal “now” semantics the user expects `11:55 → 11:59`. `PollOnceAsync` resolves From relative to the already resolved To value.

The parser also accepts From=`13:00Z`, To=`11:00Z` and sends the reversed interval. `now-1e100d` throws `OverflowException`; the Apply handler catches only `ArgumentException`, and this command is absent from the window's merged exception subscription. A malformed user entry can therefore escape the normal UI error path. The diagnostic verified the thrown type, not an application crash.

**Change:** Resolve both endpoints against the same captured instant, require From ≤ To, accept only finite supported durations, and turn all expected parse/range errors into field-level validation. Use a documented, culture-independent syntax for machine timestamps and relative expressions. Require an offset for pasted absolute timestamps, or visibly interpret them in the selected zone.

**Acceptance:** The example resolves to `11:55 → 11:59`; reversed, blank, nonfinite, overflow, and unsupported inputs never start a request or escape the UI error handler. Invalid edits preserve the last successfully applied range.

Evidence: [ElasticTailer.ParseTime/PollOnceAsync](../../src/HexTail/Elastic/ElasticTailer.cs), [ApplyElasticTimeRange and command exception subscriptions](../../src/HexTail/ViewModels/MainWindowViewModel.cs).

### 3. Saving through the setup UI must not discard hidden configuration

**Confirmed by editor round-trip.** A persisted view with two sources and namespace=`prod` becomes one source with namespace=`""` after `Sync` → `ToSettings`. The editor loads `Sources.FirstOrDefault()`, saves `Sources.Take(1)`, and explicitly empties `NamespaceValue`. The underlying persisted model still supports multiple sources and namespace values.

**Change:** Preserve unedited source/namespace data when saving. If the current product intentionally allows only one filter per view, present an explicit migration/edit choice for older configurations; do not silently rewrite them through the single-value editor.

**Acceptance:** Opening settings and saving without edits preserves all source IDs, values, and namespace mappings. Any deliberate removal is visible and explicit.

Evidence: [ElasticViewEditorViewModel.Sync/ToSettings](../../src/HexTail/ViewModels/ElasticViewEditorViewModel.cs), [Elastic settings model](../../src/HexTail/Persistence/ElasticSettings.cs).

## P1 — common work and misleading interactions

### 4. The toolbar must fit the supported minimum window

**Confirmed in rendered controls.** At 720px, the range panel is arranged into 82px instead of its normal 328px. To and Apply are offscreen; Follow and Inline are also unavailable. At 1280px, Inline disappears and the adjacent toggles crowd each other. The single horizontal `DockPanel`, fixed-width search and time inputs, and 30%/70% shell split provide no wrapping or overflow path.

**Change:** Give Elastic range controls a dedicated row or compact range flyout, and let search/view controls wrap or enter an accessible overflow menu. Preserve the primary actions at 720px.

**Acceptance:** Search, From/To/Apply, Follow, Inline, Settings, Open, and Save can be reached at 720, 1280, and 1920px in every density. Check larger fonts and scaled displays as well.

Evidence: [720px workspace](evidence/ui-2026-09-30/workspace-720.png), [1280px workspace](evidence/ui-2026-09-30/workspace-1280.png), [MainWindow layout](../../src/HexTail/MainWindow.axaml).

### 5. Users need a clear time-range model and applied-state feedback

**Observed controls and source review.** The 105px inputs are suitable for `now-5m` but cannot display a full ISO timestamp. Syntax is explained only in a tooltip. There are no common presets, timezone label, resolved interval, dirty/applied distinction, or reload progress. Follow controls scrolling; it does not stop Elastic polling. Fixed-ended ranges continue polling. The appearance setting “Time zone” changes `AppState.Now()`'s offset, but the row mapper copies timestamp field strings without formatting them in that zone, and absolute parsing does not receive the setting.

**Change:** Offer relative presets such as 5m/15m/1h/24h plus a custom absolute interval with adequate space. Show the zone and resolved interval, keep draft entries separate from the applied range, and show loading/success/error next to Apply. Label Follow as auto-scroll, and distinguish a live-ended query from a historical interval. Define precisely whether the zone controls display, input interpretation, or both.

**Acceptance:** Users can request a specific local or UTC interval without writing date math, can see exactly what was loaded, and can tell whether new logs are being fetched. All presets must use the corrected semantics in item 2.

Evidence: [range controls](../../src/HexTail/MainWindow.axaml), [AppState.Now](../../src/HexTail/Application/AppState.cs), [document rendering](../../src/HexTail/Elastic/ElasticDocumentMapper.cs), [poll loop](../../src/HexTail/Elastic/ElasticTailer.cs).

### 6. Search mode should not change implicitly when punctuation is typed

**Confirmed from command flow.** Search uses `DetectMode`, which treats any `\[](){}*+?|^$` character as a regex trigger. A normal log fragment such as `[ERROR]` is interpreted as regex rather than literal text; a query containing a lone `[` produces a regex error. The only exposed mode toggle is Match case.

**Change:** Default to literal search and add a clearly named Regex toggle beside Match case. Keep the selected mode visible and saved with each search. Preserve the existing persistent invalid-regex feedback.

**Acceptance:** `[ERROR]` finds the literal fragment in literal mode. Regex mode is an explicit choice and retains the typed query after errors. Both modes work by button and Enter.

Evidence: [CompiledQuery.DetectMode](../../src/HexTail/Domain/Search.cs), [AddSearchAsync](../../src/HexTail/ViewModels/MainWindowViewModel.cs), [SearchBar](../../src/HexTail/Views/SearchBar.axaml).

### 7. Make setup prerequisites visible before a user tries to open logs

**Observed form and source-review risks.** A data view's time field is fetched but never shown in the form. Save later reports the generic “view and field mappings are incomplete” if it is missing. An empty data-view selector gives no instruction to test the connection first. Data-view loading has no busy state; changing selections starts asynchronous loads without cancelling or rejecting an obsolete response, and success does not clear an earlier view error.

**Change:** Organize the existing form into endpoints/auth → test and metadata → data view/time field → filter → output fields → save/open. Show the detected time field, missing prerequisites, loading and empty metadata states. Reject stale data-view responses, clear resolved errors, and disable Save/Open while required metadata is unresolved. Use field-specific validation rather than a generic form error.

**Acceptance:** A first-time user can complete setup in order. A data view without a usable time field explains why logs cannot open. Rapid A → B selection cannot finish with A metadata shown under B.

Evidence: [Elastic settings form](../../src/HexTail/Views/SettingsPanel.axaml), [LoadDataViewAsync](../../src/HexTail/ViewModels/ElasticViewEditorViewModel.cs), [ValidateElasticConnection](../../src/HexTail/Application/AppState.cs).

### 8. Connection and source indicators must describe actual state

**Confirmed visually and in source.** The settings card always displays a `SuccessBrush` circle, including immediately after a failed connection test. The source flyout differentiates checking/connected/error by glyph, but does not show the status or health message as text. Its tooltip is the source description. A source-open failure is swallowed in `ToggleAsync`; the checkbox simply reverts.

**Change:** Bind card indicators to a real test/health state and display text such as Not tested, Checking, Connected, Unauthorized, or Misconfigured. Show an actionable failure beside the affected source. Keep shape/text cues alongside color; a green dot should never be the only status message.

**Acceptance:** New and failed connections do not look healthy. Opening a source with a missing credential or incomplete mapping explains the failure. Checking is visibly distinct from Connected.

Evidence: [failed test with green card indicator](evidence/ui-2026-09-30/elastic-failed-test.png), [settings card](../../src/HexTail/Views/SettingsPanel.axaml), [source checkbox flow](../../src/HexTail/ViewModels/ElasticSourceOptionViewModel.cs).

### 9. Make save/draft/destructive behavior consistent and visible

**Observed flow.** Appearance, label and exclusion changes save automatically; Elastic server/view edits require a small save icon in the server header. There is no dirty indicator or success acknowledgement, and Escape/backdrop closes settings without discussing unsaved Elastic edits. Removing a saved server immediately persists the removal and closes its open tabs. The global Save Session action does not submit Elastic editor drafts.

**Change:** Explicitly label Elastic Save, show Unsaved/Saving/Saved/Failed near the edited card, and explain autosave in other sections. On close with drafts, offer Save/Discard/Keep editing. For saved-server removal, name the affected views/tabs in a confirmation or provide a reliable undo. Do not imply Ctrl/Command+S saves a draft unless it actually does.

**Acceptance:** Users know whether configuration is stored before closing settings. Failed saves retain edits and offer recovery. Server deletion cannot silently remove configured/open views.

Evidence: [ElasticConnectionEditorViewModel.SaveAsync](../../src/HexTail/ViewModels/ElasticConnectionEditorViewModel.cs), [SettingsViewModel](../../src/HexTail/ViewModels/SettingsViewModel.cs), [server removal](../../src/HexTail/Application/AppState.cs), [dialog close behavior](../../src/HexTail/MainWindow.axaml).

## P2 — differentiation, accessibility, and inspection

### 10. Output-field selection needs an obvious starting point and preview

With a blank field-search query, only already checked fields are shown. A new view can therefore show an empty “Fields to display” area even when fields are available. Search sits below the chip area. There is no selected count, field type, or composed-row preview, and output order follows metadata enumeration rather than an explicit user choice.

**Change:** Put Search fields before the results, show an initial bounded list or an explicit Browse fields action, keep selected fields/count visible, and show a small sample composed row. Show date/searchable metadata where it helps select time/filter fields. Make output order explicit if users need it.

**Acceptance:** A new view can select its first output field without guessing that typing reveals options. Clearing a search preserves the selected summary. Save cannot silently produce an empty row configuration.

Evidence: [FilterFields/ToSettings](../../src/HexTail/ViewModels/ElasticViewEditorViewModel.cs), [field chips](../../src/HexTail/Views/SettingsPanel.axaml), [row composition](../../src/HexTail/Elastic/ElasticDocumentMapper.cs).

### 11. Strengthen selected-state contrast and theme consistency

Measured palette contrast for the selected file-tab border is:

| Theme | Against surface | Against `BorderBrush` token |
| --- | --- | --- |
| Cyber Tail | 2.72:1 | 1.76:1 |
| Catppuccin Mocha | 2.74:1 | 1.53:1 |
| Spotify | 5.02:1 | 3.84:1 |

Main text and muted text have strong contrast in all three measured palettes. Preserve that. Panel borders are subtle (1.24–1.43:1 against raised surfaces); these are mostly decorative and are not automatically accessibility failures. Selected-state cues deserve stronger differentiation. `FileStrip` also assigns a local `SurfaceBrush` background while the selected style tries to set `BorderBrush`; resolve that competing assignment when checking the actual selected fill.

The Spotify render also retains the native blue/cyan settings-tab underline and blue checked field chips while custom primary buttons are green. The same split exists between custom palette resources and Fluent control state colors.

**Change:** Use a selected indicator with at least 3:1 contrast against adjacent colors, plus a shape/weight cue. Map the Fluent accent and focus/checked/selected states to the selected theme, and inspect hover/pressed/disabled/error states without flattening their differences.

**Acceptance:** Active file/search/settings tabs and focused controls are clearly distinguishable in each theme, including grayscale. Existing black/white highlight-foreground selection is preserved.

Evidence: [palette](../../src/HexTail/ThemeManager.cs), [selected file style](../../src/HexTail/Styles/CyberTail.axaml), [Spotify controls](evidence/ui-2026-09-30/elastic-spotify.png). Benchmark: [W3C non-text contrast](https://www.w3.org/WAI/WCAG22/Understanding/non-text-contrast.html), [text contrast](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html), and [use of color](https://www.w3.org/WAI/WCAG22/Understanding/use-of-color.html).

### 12. Complete keyboard and accessible naming for custom controls

Toolbar Open/Save/Settings and tab-close actions already have accessible names; Match case and Escape-to-close also exist. Most settings icon actions, time inputs, color pickers, and custom form fields lack explicit names/label associations. Nearby `TextBlock` labels and hover tooltips are not evidence of correct screen-reader labeling. Row expansion is wired to pointer double-tap only, and tab reordering is pointer-only.

**Change:** Associate visible labels with inputs, name custom icon controls, expose row details with Enter/Space or a named action, and provide a keyboard reorder option when reordering is required. Verify modal focus entry, containment and restoration; do not assume DialogHost covers them. Check small close targets in Compact density (20px in existing tests) without enlarging every visual icon.

**Acceptance:** A keyboard-only pass can open/configure an Elastic source, apply a range, search, inspect a row, and close settings with focus restored. A screen reader announces purpose, state and errors for those controls. This acceptance check still requires native assistive-technology testing.

Evidence: [MainWindow.OnKeyDown](../../src/HexTail/MainWindow.axaml.cs), [settings inputs](../../src/HexTail/Views/SettingsPanel.axaml), [row gestures](../../src/HexTail/Views/LogLineView.axaml.cs), [tab reorder](../../src/HexTail/Behaviors/TabReorderBehavior.cs).

### 13. Make full log text and structured fields easy to inspect and copy

Raw rows are nonselectable text blocks with `NoWrap` and ellipsis. Parsed fields expand on double-click, but there is no visible expand affordance or explicit copy action. A long raw message can be truncated even when the operator needs its exact contents.

**Change:** Add a compact row action/context menu for Copy line, Copy fields and Expand details, with keyboard equivalents. Make the full raw value available in the existing details area; keep the main virtualized row compact.

**Acceptance:** A long message and structured Elastic document can be read and copied exactly without changing the output-field configuration. Copying respects the selected row and does not stop scrolling unexpectedly.

Evidence: [LogLineView](../../src/HexTail/Views/LogLineView.axaml), [row interaction handlers](../../src/HexTail/Views/LogLineView.axaml.cs).

### 14. Settings should reflow instead of requiring horizontal navigation

The minimum-width labels/exclusions render clips the Exclusions section and its add action to the right. The existing horizontal scrollbar makes the content reachable but requires users to discover it. Nested expanded server/view cards also create long scrolling forms. The dialog is nominally 1600×920 and merely constrained by the window.

**Change:** Stack the two settings columns below a practical width, collapse inactive server/view cards, and keep save/error actions within the visible editing section. Keep vertical scrolling and avoid fixed input widths that force horizontal scrolling.

**Acceptance:** Every settings action and its label is visible without horizontal scrolling at 720px, and larger fonts do not hide actions or validation text.

Evidence: [labels at 720px](evidence/ui-2026-09-30/labels-720.png), [SettingsPanel layout](../../src/HexTail/Views/SettingsPanel.axaml).

### 15. Save the applied time range with the session

Applied expressions exist on the in-memory file tab, but `PersistedElasticTab` and `AppState.SaveAsync` omit them. Saving a session and reopening an historical investigation resets the source to `now-5m → now`.

**Change:** Persist the successfully applied expressions and range mode per Elastic tab. Show a restored range before its request starts. Decide explicitly whether a saved relative range moves with the clock; preserve fixed absolute intervals exactly.

**Acceptance:** Ctrl/Command+S → restart restores an absolute interval, its searches, and source without silently querying the latest five minutes.

Evidence: [PersistedElasticTab](../../src/HexTail/Persistence/AppConfig.cs), [SaveAsync](../../src/HexTail/Application/AppState.cs), [tab range defaults](../../src/HexTail/Application/FileTabState.cs).

### 16. Distinguish result states and disclose the initial result cap

The main log list has no loading/empty message. Only the no-open-file state and empty inline-context state have explanatory copy. A connected but empty interval, a search with zero matches, and a waiting initial query can leave a mostly blank workspace. The Elastic initial load intentionally takes only the newest configured number of rows (10,000 by default), but the range UI does not disclose that cap.

**Change:** Show Connecting/Loading, No logs in this interval, No matches, and Failed as distinct states with a relevant recovery action. Display the applied interval, returned row count and whether initial results reached the cap. Explain that turning Follow off stops auto-scroll rather than retrieval.

**Acceptance:** Empty history cannot be confused with a failed connection, and reaching the cap cannot be mistaken for an exhaustive historical search. Preserve the bounded initial load rather than fetching unbounded history.

Evidence: [LogWorkspace](../../src/HexTail/Views/LogWorkspace.axaml), [LogView](../../src/HexTail/Views/LogView.axaml), [initial load limit](../../src/HexTail/Elastic/ElasticTailer.cs).

## P3 — discovery and convenience

### 17. Improve tab navigation as the workspace grows

File/source names can be long; close controls share the header and the selected file is mainly distinguished by border/background. Search tabs show their query and match count, which should remain. Dragging reorders tabs, but there is no indication of that interaction or keyboard alternative.

**Change:** Add a bounded header with full name/source details on demand, a clear overflow navigation path, and a reorder hint or menu action. Keep All fixed and preserve the current tab's identity when moving it.

**Acceptance:** Ten long file/source tabs remain individually selectable and closable at the supported window widths. Selecting, closing and reordering do not unexpectedly activate another source.

Evidence: [FileStrip](../../src/HexTail/Views/FileStrip.axaml), [search tabs](../../src/HexTail/Views/LogWorkspace.axaml), [TabReorderBehavior](../../src/HexTail/Behaviors/TabReorderBehavior.cs).

### 18. Make Elastic discoverable before it is configured

The empty workspace says only “Open a file to start tailing,” and the source toolbar button is hidden until sources exist. A user looking for Elastic must discover it through the settings gear. The user guide still describes manual server/namespace pairs, while the current visible editor presents a single generic Filter field/Value per view; it also lacks a time-range walkthrough.

**Change:** Offer Open file and Set up Elastic in the empty state. Add concise endpoint/authentication, data-view/time-field, filter, output-field and time-range instructions beside the form or in a short linked guide. Update documentation to match the chosen preservation/migration behavior in item 3.

**Acceptance:** A first-time user can discover Elastic, configure one source, and load a chosen historical interval without guessing terminology or date syntax.

Evidence: [empty workspace](../../src/HexTail/Views/LogWorkspace.axaml), [source button visibility](../../src/HexTail/MainWindow.axaml), [user guide](../user-guide.md).

## Suggested delivery order

1. **Correctness:** items 1–3, with targeted regressions for range replacement, same-clock parsing, malformed input, and unchanged configuration round-trip.
2. **Usable historical investigation:** items 4–5 and 15–16, using the corrected query lifecycle. Verify minimum-width layouts and absolute/local/UTC ranges.
3. **Reliable setup and search:** items 6–10. Verify first-time setup, failures, edits, saves, and opening a source end to end.
4. **Whole-app polish:** items 11–14 and 17–18, including native keyboard/screen-reader/scaling checks.

Keep changes local to the existing controls and state flow. A redesign framework, new component library, or conversion of log rows into a grid is not required to address this backlog.
